# 思源任务块识别与映射（文档任务块 ⇄ CalDAV VTODO）

> 对应 GitHub issue #2。本文件是功能说明 + 实现方案 + 界面改动的总文档，供核对是否遗漏。
> 提交：`c5b485c feat: 文档任务块 ⇄ VTODO 识别与映射（issue #2）`（**尚未发版**）。

---

## 1. 功能概述

把思源文档里用原生语法写的任务块：

```markdown
- [ ] 待办1
- [x] 已完成的待办
```

自动同步成 CalDAV VTODO（待办），可在手机端（Tasks.org / DAVx⁵ 等）管理：

- **文档里打勾** → 服务端 VTODO 标完成；
- **手机端标完成** → 思源里的块勾选态跟着打上；
- **文档里的块被删除** → 对应的 VTODO 一并删除；
- **在插件里删除该 VTODO** → 思源里的块也一并删除。

识别与映射分两种入口：

1. **批量扫描**：每轮同步末尾自动扫一遍（范围可配），也支持设置页「立即扫描」。
2. **单笔转换**：在思源里右键某个任务块，用块菜单手动同步或取消同步（见第 6 节）。

## 2. 实现方案

### 2.1 身份锚点：Block ID（不是文本匹配）

每条由任务块转来的 VTODO，在其 ICS 里写入一个自定义属性：

```
X-SIYUAN-BLOCK-ID: 20261028123456-abcdef
```

- 该属性被纳入 ICS 的 `MANAGED` 属性集，**手工编辑/服务端回写时不会丢，也不会重复拼一次**（`src/core/ics.ts`）。
- 映射关系以 Block ID 为准，**改文字、改标题、甚至插件配置清空后都能靠服务端这份属性重建映射**，不会因为文字对不上就失联。
- 这是与编辑器里「手工新建待办」的唯一物理区别：编辑器建的 VTODO 没有 `X-SIYUAN-BLOCK-ID`，不会被当成本地任务块。

### 2.2 三方对账

每轮扫描跑一次对账，对比三方状态：

| 来源 | 内容 |
| --- | --- |
| ① 文档侧 | 内核 SQL 扫出来的任务块（id / 文字 / 勾选态） |
| ② 服务端侧 | 同步拉回的 VTODO（含 `X-SIYUAN-BLOCK-ID`） |
| ③ 本地 store | 已建立的映射（`CalItem.blockId` + 缓存的 `blockText`/`blockChecked`） |

产出四类动作：

- **create**：块有、映射无、服务端也无 → 新建 VTODO。
- **push**：块侧改了（文字/勾选）→ 推服务端。
- **writeback**：服务端完成态变了 → 回写块的勾选态。
- **delete**：块没了（按 ID 直接查在不在，不受扫描范围影响）→ 删 VTODO。

> ⚠️ **删除判生死按 Block ID 直接查存在性**，不靠扫描范围。
> 这样「文档被删且当时没打开」「笔记本被删」都能正确跟删 VTODO；
> 反过来，块只是「不在本次扫描范围内」（文档关着、不在指定笔记本）**绝不能误删**。

### 2.3 状态映射与冲突

| 方向 | 规则 |
| --- | --- |
| 块 → VTODO | `checked` → `COMPLETED/percent=100`，否则 `NEEDS-ACTION/percent=0` |
| VTODO → 块 | `COMPLETED` → 块打勾 `- [X]` |
| 文字 | **一律以块为准**（详见 2.4） |
| 完成优先 | 两边都动了、其中一边是完成 → 按完成处理（完成是终态，不会来回翻转） |

待办块没有「放弃」状态，对应到 VTODO 只有「完成 / 未完成」两态（按完成映射）。

### 2.4 为什么不回写块文字（重要设计取舍）

块的 `content` 是纯文本，但块里可能有**加粗、行内代码、引用 `((id "文本"))`、图片**等富文本。
若用纯文本 `updateBlock` 回写，会把富文本一律拍平、毁掉格式。

因此约定：**文字永远跟随块**，服务端标题只是块的镜像。

- 块改了文字 → 推服务端（服务端被别的客户端改的标题，下一轮会被块覆盖回来）；
- 服务端改了文字 → **不**回写块（避免毁格式）。
- 需要「手机端也能改名并写回文档」的诉求，需另行评估（得改成 DOM 级增量改写），本期不做。

## 4. 配置清单

「设置 → 思源任务块识别与映射」区域，受**总开关** `blockSyncEnabled`（默认关）控制；关闭＝完全停用（不扫描、无块菜单、不同步、「立即扫描」只提示未启用）。

| 配置项（key） | 界面文案 | 取值 | 默认 | 说明 |
| --- | --- | --- | --- | --- |
| `blockSyncEnabled` | 启用文档任务块识别与映射 | 开关 | 关 | 总开关，关则全功能停用 |
| `blockSyncCalendarUrl` | 文档任务块转 VTODO 的默认日历 | 空 / 某日历 | 空 | 空＝复用「新建条目的默认日历」及其回退链 |
| `blockSyncDefaultEnd` | 默认结束时间 | `sameAsTodo` / `none` | `sameAsTodo` | `sameAsTodo`＝跟随「新建待办任务时默认结束时间」；`none`＝无日期任务（不写 DUE） |
| `blockSyncScope` | 自动扫描范围 | `open` / `daily` / `notebooks` / `all` | `all` | 打开的文档 / 仅日记 / 笔记本 / 全部文档 |
| `blockSyncNotebooks` | 指定笔记本（范围=笔记本时多选） | string[] | `[]` | 范围选「笔记本」才出现，列出本工作区全部笔记本多选 |
| `blockSyncMarks` | 标记 | `["badge"]` / `["prefix"]` / 两者组合 | `["badge"]` | 加「文档」小角标（纯 UI）/ 自定义前缀（写进标题） |
| `blockSyncPrefix` | 自定义前缀文本 | 任意串 | `[文档]` | `blockSyncMarks` 含 `prefix` 时写入 VTODO 标题，形如 `[文档]待办1` |

> 基准时间口径与编辑器一致：开始＝今天下一个整点，结束＝开始 +（1h 或 8h，依 `todoDefaultEnd`），全天待办沿用「次日」兜底。

## 5. 界面改动

### 5.1 设置页新增区域

「思源任务块识别与映射」卡片，含：总开关、默认日历、默认结束时间、扫描范围（选「笔记本」展开多选列表）、标记（角标 / 前缀，勾前缀出现输入框）、以及两个动作按钮：

- **立即扫描**：当场扫一遍（不等同步周期），结果显示在右侧提示区。
- **一键清理**：删掉全部由任务块转来的 VTODO（**文档里的块不动**），**二次点击确认**（5 秒窗口内再点一次才执行，不用 `confirm()`），结果回显。
  - ⚠️ 若开关仍开着、范围仍覆盖着，下一轮同步会重新建回来 —— 后悔了用它清空，顺手关开关即可。

### 5.2 任务视图 / 侧栏角标

来自文档任务块的待办，在标题前加一个「**文档**」小角标（`[文档]` 文字或文档图标，取决于视图），提示它源自思源任务块、双向联动。可在设置里关掉（纯 UI，不动数据）。

### 5.3 单笔映射菜单（重点）

**位置：在思源文档里，右键某个任务列表块（或点块左侧的图标把手 / `⋮⋮` 拖拽手柄唤出的菜单），弹出的块右键菜单里。**

- 该入口由 `eventBus.on("open-menu-content", …)` 钩子注入（`src/index.ts` 的 `onBlockMenu()`）。
- **必须先打开总开关**，否则菜单不出现。
- 菜单项**三态**，取决于该块当前状态：

| 块状态 | 菜单项 | 行为 |
| --- | --- | --- |
| 未同步 | 「同步此任务到 CalDAV」 | 单笔建 VTODO，写 `X-SIYUAN-BLOCK-ID` 锚定 |
| 已同步 | 「取消同步（删除对应的 CalDAV 待办）」 | 删 VTODO + 给块打 `custom-caldav-skip` 忽略标记（**见 5.4**） |
| 已忽略 | 「重新同步到 CalDAV」 | 清标记 → 立刻重建 VTODO |

> 菜单钩子全程 try/catch，插件异常不会污染思源右键菜单体验。

### 5.4 「取消同步」为什么必须打忽略标记

只删 VTODO 而不标记，下一轮扫描会把它当成陌生块**再建一个**（正是实现中堵掉的洞）。
忽略标记 `custom-caldav-skip` 打在**块自身属性**上（不是配置里），所以配置清空 / 插件重装后标记还在，不会被扫回来。

## 6. 删除语义（双向）

| 操作 | 结果 |
| --- | --- |
| 文档里删除任务块 | 按 ID 查到块已不存在 → 删对应 VTODO |
| 在插件 UI 删除该 VTODO | 删除块（`updateBlock` 删除块节点） |
| 删文档 / 删笔记本（当时没打开） | 按 ID 查存在性 → 块已不在 → 跟删 VTODO |
| 块菜单「取消同步」 | 删 VTODO + 打 `custom-caldav-skip`（不删块，且不再被扫描重建） |
| 设置「一键清理」 | 删全部块来源 VTODO（**不删块**），下轮若开关+范围仍覆盖会重建 |

## 7. 已知限制 / 待你核对的点

1. **手机端改标题不回写文档**（2.4 取舍）：文字以块为准。若你希望「手机端改名也写回文档」，需评估 DOM 级增量改写，本期未做。
2. **文字冲突策略预留未启用**：`planBlockSync` 有 `conflict` 入参（local/server），但目前文字一律以块为准，`conflict` 仅占位（`void conflict`）。后续若开放「服务端优先」再接上。
3. **引用 / 富文本块**：扫描以 `content`（纯文本）为准；引用 `((id "文本"))` 在块文字里已还原为纯文本，转 VTODO 标题时不含链接。
4. **扫描上限**：内核 SQL 显式 `LIMIT 5000`，超大量的库可能被截断（本机实测任务块 97 个，远低于上限）。
5. **「打开的文档」范围**：若当前没有任何文档打开，扫描结果为空（**不会退化成全库**）。
6. **Obsidian 端**：本期只改思源端；Obsidian 没有「块」概念，本次不涉及（Obsidian 仓全量测试仍绿）。
